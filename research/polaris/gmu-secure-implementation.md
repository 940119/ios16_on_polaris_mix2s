# Polaris A630v2 secure GMU → headless CP fence implementation contract

**Status (2026-10-23): source-only engineering specification, not a hardware driver or a tested GPU path.** No phone action, image, push, register access or firmware execution was performed for this document. Keep the existing CPU framebuffer and 0090 touch path as default and on every error. The opt-in `polarisgpu=1` in [0093](../../xnu/patches/0093-polaris-gpu-disabled-bringup-gate.patch) deliberately stops at its unimplemented firmware stage; [0091](../../xnu/patches/0091-polaris-gpu-readonly-firmware-diagnostic.patch) validates metadata but does **not** return an attested firmware capability or check signatures. [0092](../../xnu/patches/0092-polaris-gpu-readonly-arc-command-db.patch) withdrew an unsafe fixed-PA command-DB map. Thus a hardware-writing `0095` patch is **not justified yet**.

## Exact boundary and proposed XNU API

Split the new implementation into private `bsd/dev/polaris_gpu_secure.{h,c}`, `polaris_gpu_smmu.c`, `polaris_gpu_gmu.c`, and `polaris_gpu_cp.c`, but compile none of the hardware backends by default until each owner is established. Do not copy GPL Linux C into the APSL XNU tree. In particular, do not turn [0093](../../xnu/patches/0093-polaris-gpu-disabled-bringup-gate.patch)'s `completed` counter into an ownership certificate. A successful *read* or pre-existing `PWR_ON` is never an acquired resource.

```c
/* Private API sketch: return errno, not bool; one owner and one attempt per boot. */
struct pg_context;
struct pg_blob { uint64_t pa; uint32_t bytes; }; /* exact ADT bounds, not authentication */
struct pg_iova { uint64_t base, bytes; uint32_t prot; };
struct pg_backend {
    int (*acquire_power)(struct pg_context *);  /* owned CX, clocks, RPMh/DDR */
    int (*acquire_smmu)(struct pg_context *);   /* distinct GMU/core domains */
    int (*start_gmu)(struct pg_context *, const struct pg_blob *flat_gmu);
    int (*hfi_boot)(struct pg_context *);       /* ACK-verified, bounded */
    int (*pas13_auth)(struct pg_context *, const struct pg_blob zap[4]);
    int (*cp_test)(struct pg_context *, const struct pg_blob *sqe);
    int (*quiesce)(struct pg_context *);        /* bounded CP+GMU idle */
    void (*release_owned)(struct pg_context *); /* only after quiesce */
};
```

A separate per-resource ledger records `ACQUIRED_BY_US`, `OBSERVED_FOREIGN`, or `UNKNOWN`, the original value, an actual readback, and a release callback; set `ACQUIRED_BY_US` **only after** the vote/transition's ACK and readback. `UNKNOWN`/timeout after firmware starts means quarantine until reboot: stop submissions and all user clients, keep memory pinned and the acquired supply votes rather than free a live page table or blindly collapse shared CX/GX. The vendor [`gmu_stop`](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/kgsl_gmu.c#L1502-L1546) waits for idle/slumber first; a failed wait enters fault handling. The [HackiOS 22-stage structure](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L3791-L3799) illustrates rollback architecture, **not** matching SDM845 constants.

Run entry in a kernel thread after 0093's existing dual-ADT `xiaomi,polaris` + `qcom,sdm845` gate and exact `polarisgpu=1`. Also require runtime A630v2 identity confirmation rather than trust vendor static `0x06030000` DTS: recovery reports 630v2 and 257–710 MHz, whereas [mainline catalog](https://github.com/torvalds/linux/blob/7be4bc52fd9e0e55dc9a2e0232b89427d2c4b614/drivers/gpu/drm/msm/adreno/a6xx_catalog.c#L947-L968) admits `0x06030001/2`. Never read GPU/GMU ID registers before their **owned, proven-on** domain. Before making any MMIO map, check each physical region against a board-specific resource table and page bounds, and check reservations against the actual boot ADT. The preflight in [tools/polaris_gpu_preflight.py](../../tools/polaris_gpu_preflight.py) verifies six **locally kept** firmware file lengths and layout and 0xdea000 payload cap, but cannot establish runtime XNU domain ownership or authenticity.

### Dependency order and blockers (all must be solved before headless submission)

1. **Rails/clock/RPMh and bandwidth:** MiCode [GPUCC v2 fixup](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/clk/qcom/gpucc-sdm845.c#L606-L640) changes GMU source and GPU frequencies; CX/GX GDSCs share the `0x05090000` physical window, and the [vendor start](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/kgsl_gmu.c#L1397-L1433) acquires CX, GMU clocks/IRQs, temporary DDR vote **before** RPMh/PDC/ITCM/HFI. Local `sweet_rpmh.c` controls Sweet ldoc11 only and is not a Polaris voltage API. Need real owner/ACK for apps-RSC `0x179e0000` TCS at `0x179e0d00`, and ARC `gfx.lvl/cx.lvl/mx.lvl`; current recovery does not expose a trusted command-DB read-only interface. A `PWR_ON` read is not permission to clear CX/GX. No direct GPUCC/GDSCR write or GMU MMIO read until this contract is implemented. See [ownership contract](a630v2-bringup-contract.md).
2. **GPU SMMU before DMA:** vendor [GPU DT](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/arch/arm64/boot/dts/qcom/sdm845-gpu.dtsi#L268-L359) describes SMMU `0x05040000`, *separate* GMU and 3D contexts and HYP-protected CB5–7. `qcom,protect=<0x40000 0xc000>` is **relative** and outside the node's `0x10000` register aperture; do not map or write it. Implement `pg_smmu_attach(domain, exact_stream_ids, restricted_iova, fault_callback)` only after deriving the Polaris context/stream routing from the actual DT/vendor SMMU integration and proving HYP permits those nonprotected banks. Reject already-owned SMR/S2CR and unknown IDR aperture/page size. Page tables must map **only** the pinned GMU firmware/HFI/log and CP ring/SQE/scratch pages needed; no wildcard SMR or identity-map of all DRAM. DSB/cache maintenance, bounded TLB sync and fault checks are required both before GMU fetch and after each submit. The Pixel A530 [wildcard stream + 1GB identity map](https://github.com/joranv1/ios-sailfish/blob/ce637521bacc06fab5cc29cf144febee2fca9ff8/xnu/patches/0121-sailfish-gpu-smmu-identity.patch#L16-L63) is a **specific anti-pattern** here. Fail before any firmware start if an independent GMU or core domain cannot be safely attached.
3. **GMU image and boot:** device's `a630_gmu.bin` is a flat 32,768-byte CM3 ITCM image (host preflight checks initial stack/Thumb entry); vendor `TCM_BOOT` loops `MAX_GMUFW_SIZE=0x2000` **32-bit writes**, not 0x2000 bytes ([MiCode](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/adreno_a6xx.c#L1790-L1828)). Do not feed it to HackiOS A660's 16-byte block parser. Allocate/map HFI queue table plus log in the GMU's IOVA space, verify host-visible/GMU-visible addresses, configure PDC/RSC, load ITCM with bounded indexed writes/readback as permitted, reset CM3, poll fresh `CM3_FW_INIT_RESULT`, then `HFI_CTRL_STATUS`, with a hard deadline and watchdog/CM3-fault reporting. [Mainline boot sequence](https://github.com/torvalds/linux/blob/7be4bc52fd9e0e55dc9a2e0232b89427d2c4b614/drivers/gpu/drm/msm/adreno/a6xx_gmu.c#L929-L1065) provides register ordering, not proof that XNU owns PDC/RSC. No `nogmu` fallback is established for this phone.
4. **HFI protocol:** implement `pg_hfi_send(id, payload, dwords, expected_ack, deadline)` with queue lock, producer/consumer range and free-space checks, cache clean + release barrier before host→GMU interrupt, bounded wait, ACK ID **and** sequence match, response size and FW error validation; a timeout never counts as success. The vendor [`hfi_init`/`hfi_send_msg`](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/kgsl_hfi.c#L66-L259) uses dword queue sizes, sequence numbers and an ACK timeout. For the vendor v1 path, order is `INIT` → FW_VERSION → PERF_TBL → BW_VOTE_TBL (then vendor quirk TEST), not a raw start bit; see [`hfi_start`](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/kgsl_hfi.c#L572-L622). Mainline [`a6xx_hfi_start_v1`](https://github.com/torvalds/linux/blob/7be4bc52fd9e0e55dc9a2e0232b89427d2c4b614/drivers/gpu/drm/msm/adreno/a6xx_hfi.c#L937-L969) similarly differs from the newer nonlegacy START protocol. The vendor BW table is **13 DDR + 2 CNOC use cases** from `msm_bus_scale_query_tcs_cmd_all` ([MiCode](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/kgsl_gmu.c#L684-L784)); `IB(KBps)` alone cannot produce cmd addresses, BCM aux, aggregation, completion masks or vote words. Mainline A630 has a [fixed single DDR-off + two CNOC reference](https://github.com/torvalds/linux/blob/7be4bc52fd9e0e55dc9a2e0232b89427d2c4b614/drivers/gpu/drm/msm/adreno/a6xx_hfi.c#L761-L796), **not proven accepted by this phone's GMU or equivalent to vendor 13-case scaling**. Do not send either guessed HFI table until independently validated owner-derived query output or an explicitly bounded, separately authorized mainline-mode compatibility experiment exists. A test `INIT` alone is still a power/firmware experiment, not read-only diagnostics.
5. **PAS13 secure zap:** [Polaris reservation](sdm845.dtsi#L550-L554) `0x8c415000..0x8c417000` is only 8KiB, no-map, not general BO RAM. Local `.mdt` 6684 bytes has one non-hash PT_LOAD `.b02` 1968 bytes at ELF paddr `0x5000` (other `.b00/.b01` are metadata/hash); offline parser only validates shape. Define `pg_pas13_init(meta_pa, meta_len, segment_pa, segment_len, reserved_pa, reserved_len)` only after platform owners confirm whether TZ owns this carveout at XNU handoff, whether `PAS_IS_SUPPORTED`/`PAS_SHUTDOWN` are available, SCM calling convention, metadata coherency, and correct `qcom_mdt_load` offset/relocation semantics. The sequence to *implement and validate*, not blindly execute, is `PAS_INIT_IMAGE(13, metadata)` → `PAS_MEM_SETUP(13, validated base, validated size)` → copy/zero **only** an authorized target interval → clean cache → `PAS_AUTH_AND_RESET(13)` and verify both transport and secure result; make no assumption that successful XNU blob parsing authenticates firmware. A530 Sailfish [PAS example](https://github.com/joranv1/ios-sailfish/blob/ce637521bacc06fab5cc29cf144febee2fca9ff8/xnu/patches/0130-sailfish-gpu-zap-shader.patch#L74-L146) hard-codes a different 1MiB region and cannot be pasted. HackiOS [A660 PAS](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L2623-L2692) has a closer 8KiB region but still different PA/ELF and its inference that failure means an earlier authenticated shader exists is **not** a safe Polaris success criterion. On any ambiguous SCM response, quarantine, do not disable GPU secure mode.
6. **Bounded, headless CP proof:** only after authenticated PAS13, verified GMU/HFI and SMMU with zero faults, map one zeroed 16KiB-or-smaller command ring, a distinct SQE page (actual 32136-byte firmware needs its whole pinned mapped range), and a distinct 16KiB scratch/fence page at exact GPU IOVAs. Program **A6xx SQE** (`A6XX_CP_SQE_INSTR_BASE_{LO,HI}` in [MiCode](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/adreno_a6xx.c#L832-L859)), not A5xx PM4/PFP bases or A530 ME_INIT. A6xx-specific validated packet emitter first issues bounded `CP_MEM_WRITE` to a scratch sentinel and then a cache-flush timestamp/fence event into a different 32-bit word. Pre-fill `sentinel=0`, `fence=0`, use monotonic seq=1, clean ring/scratch, release barrier, update WPTR **once**; poll RPTR/fence and faults with a monotonic <=200ms deadline (never unbounded loops). Require both `fence==1` **and** `sentinel==expected`, plus no GMU/SMMU/CP fault; fence or RPTR movement alone is insufficient GPU-memory proof. After invalidate/readback, submit no second command or user-controlled BO. The analogous A530 scratch probe and 200ms deadline appear in [Sailfish 0120](https://github.com/joranv1/ios-sailfish/blob/ce637521bacc06fab5cc29cf144febee2fca9ff8/xnu/patches/0120-sailfish-gpu-cp-test.patch#L149-L241), but its opcodes, register addresses, secure-mode shortcut and SMMU identity map are not A630-ready. No display flip, IOSurface wrapping, Mesa bridge, user client or debugfs exposure in this phase.

## Conservative viable next change

Do **not** create 0095 as a fake powered GPU patch. In a new *separately reviewed* patch, strengthen the existing [0093](../../xnu/patches/0093-polaris-gpu-disabled-bringup-gate.patch) gate by factoring a **pure, no-MMIO validation function**: explicit `pg_validate_handoff(ADT, blob_bounds, reserved_ranges, expected_hashes)` returns an immutable preflight result; require six exact local file hashes as well as lengths, 16KiB alignment and overflow-safe interval checks, zap/splash exclusion, and exact dual ADT identity. Expose stage/owner ledger in private unit tests (including timeout and foreign-owner cases), but leave all `pg_backend` callbacks absent and the boot path returning `ENOTSUP`; existing CPU framebuffer continues. The firmware hashes bind the known local device files, **not** cryptographic secure boot. Existing [0091](../../xnu/patches/0091-polaris-gpu-readonly-firmware-diagnostic.patch) is a compile-verified (not phone-run) starting point; a new compile can be deferred until the ownership-facing interfaces are designed. Independently obtain a legitimate owner-exported command-DB/BCM+bus query snapshot and Polaris GPU SMMU stream/context routing; these are the first two concrete inputs that can unlock a *real* powered patch. Do not read recovery-owned raw `/proc/iomem` through `/dev/mem`, map fixed XNU command-DB PA, run a new phone image or push in this research task.

**Stop conditions:** no trusted command-DB/bandwidth table; inability to acquire CX/DDR/GPUCC without clobbering a foreign vote; unavailable non-HYP SMMU bank/stream ownership; unknown XNU PAS13 reservation and SCM response; GMU/HFI timeout; any SMMU/CP fault; or unproven idle on teardown. Each condition leaves GPU disabled/quarantined and CPU scanout unchanged. Build/link success, a GMU version string, or a moving CP RPTR are not evidence of iOS GPU acceleration.
