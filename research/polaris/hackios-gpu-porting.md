# HackiOS A642L 对 Polaris A630 的可用性核对（2026-10-22）

- 固定源码：[`hackios-xnu-kernel` `8e61187098f2c26c5daee8f9f72b6416aa64b9ab`](https://github.com/oosexgang/hackios-xnu-kernel/tree/8e61187098f2c26c5daee8f9f72b6416aa64b9ab)，以及配套 [`hackios-xnu-userland` `906425b75e02b4f99eb5d7bb1ef7c9583472d772`](https://github.com/oosexgang/hackios-xnu-userland/tree/906425b75e02b4f99eb5d7bb1ef7c9583472d772)。本地克隆仅在忽略的 `out/research-hackios-*`。两仓库遵循 APSL 2.0；本次**没有复制它们的驱动源码**。
- **可复用的流程**：[Redwood `redwood_adreno.c` 的 22 个阶段](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L3791-L3799)把 CX/时钟、GMU、SMMU、PAS zap、CP 命令、首帧分开；[反向清理](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L3033-L3114)先等待/隔离正在使用的 GPU 缓冲区，再释放 HFI、PAS、SMMU 映射和电源。Polaris 未来的 headless fence 测试应照搬**阶段、断言、超时、撤销状态机的设计**，而不是寄存器常量或写入顺序。
- **关键不兼容（已用于离线预检）**：Redwood `a660_gmu.bin` 按 `address,size,type,value` 16 字节块解析、分配额外内存、装入 ITCM/DTCM 和 SMMU 映射：[源](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L1700-L1769)。Polaris 设备提取的 `a630_gmu.bin` 为 32768 字节，前两字是 `0x43f80`（栈指针）和 `0x9`（Thumb 入口），不是该 16 字节块头。MiCode A630 [TCM_BOOT 路径](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/polaris-o-oss/drivers/gpu/msm/adreno_a6xx.c#L1790-L1828)将 flat image 保存在共享缓冲，并向 GMU ITCM 写入 `MAX_GMUFW_SIZE` 个 32 位字；该宏在 `kgsl_gmu.h` 是 `0x2000`，**单位为循环次数而非字节数**。因此需独立核对 Polaris 32KiB 固件和 8192 次写入，绝不能把 Redwood 分块装载器直接改文件名。`tools/polaris_gmu_firmware.py` 已做离线长度/向量门槛并在组包预检执行；这是格式辨别，不是安全认证或硬件装载验证。
- **不能直接移植的常量**：Redwood SC7280 GPU `0x03d00000`，GPUCC `0x03d90000`，SMMU `0x03da0000`，[zap carveout `0x8b71a000`、`a660` PAS 流程](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L2600-L2669)，以及 [只给 HFI 一档关机 DDR、CNOC 表](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/bsd/dev/redwood_adreno.c#L2283-L2349)。Polaris SDM845 的 GPU/GPUCC/SMMU 分别是 `0x05000000/0x05090000/0x05040000`，zap 仅有设备观测 `0x8c415000` 8KiB，GMU 路径需要由 Polaris 固件、时钟和受保护 SMMU 再核对；厂商 GMU DDR 13 档、CNOC 2 档通过 BCM 拓扑计算，不能用 Redwood 的硬编码 `SH0/MC0/ACV/CN0` 表冒充真机数据。
- **GPU 启动后可借鉴的接口，而不是现在移植**：[RedwoodGPU.cpp](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/xnu/files/iokit/Kernel/RedwoodGPU.cpp) 给 Mesa 一个 msm DRM 子集（BO/IOVA/submit/wait fence），并借 IOSurface 共享呈现；[redwood_drm.c](https://github.com/oosexgang/hackios-xnu-userland/blob/906425b75e02b4f99eb5d7bb1ef7c9583472d772/tools/mesa/redwood-drm/redwood_drm.c#L1-L103) 把 ioctl 号转成 IOKit user-client selector。Redwood 明示多进程隔离和同步设施仍有限；Polaris 首先应验证真实 CP fence 和像素写入，再设计用户态 ABI，保留 CPU framebuffer 回退。
- [PORTING.md](https://github.com/oosexgang/hackios-xnu-kernel/blob/8e61187098f2c26c5daee8f9f72b6416aa64b9ab/docs/PORTING.md#L46-L64)也明确 GPU 是设备专用，初次启动仍应只用 framebuffer、触摸和 CPU。本项目不改现有可用的 0090 触摸和显示；无需为离线格式核对跑 CI，更未在手机上执行/刷写任何代码。
